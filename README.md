# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Если база уже запущена, примени новую миграцию вручную:

```bash
# PowerShell
Get-Content migrations/0002_add_recurrence.up.sql | docker compose exec -T postgres psql -U postgres -d taskservice
```

## Swagger

```text
http://localhost:8080/swagger/
```

## API

Базовый префикс: `/api/v1`

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/tasks` | Создать задачу |
| `GET` | `/tasks` | Список задач |
| `GET` | `/tasks/{id}` | Получить задачу по ID |
| `PUT` | `/tasks/{id}` | Обновить задачу |
| `DELETE` | `/tasks/{id}` | Удалить задачу |
| `POST` | `/tasks/recurring` | Создать периодические задачи |

---

## Фича: периодические задачи

### Описание решения

При создании периодической задачи пользователь передаёт правило повторения и диапазон дат. Сервис вычисляет все подходящие даты и создаёт отдельную задачу на каждую из них. Каждая задача независима — её можно редактировать и удалять по отдельности.

Правило повторения сохраняется в таблице `task_recurrences`. Каждая сгенерированная задача ссылается на это правило через `recurrence_id` и хранит свою дату в поле `scheduled_date`.

### Endpoint

```
POST /api/v1/tasks/recurring
```

### Типы периодичности

| `type` | Обязательные поля | Описание |
|---|---|---|
| `daily` | `every_n_days` | Каждые N дней начиная с `start_date` |
| `monthly_days` | `month_days` | Конкретные числа месяца, например `[1, 15]` |
| `specific_dates` | `specific_dates` | Точные даты |
| `parity` | `parity` | Чётные (`"even"`) или нечётные (`"odd"`) числа месяца |

### Примеры запросов

**Каждые 2 дня:**
```json
{
  "title": "Обзвон пациентов",
  "description": "Ежедневный обзвон",
  "status": "new",
  "start_date": "2025-05-01T00:00:00Z",
  "end_date": "2025-05-31T00:00:00Z",
  "recurrence": {
    "type": "daily",
    "every_n_days": 2
  }
}
```

**1-го и 15-го числа каждого месяца:**
```json
{
  "title": "Формирование отчётности",
  "status": "new",
  "start_date": "2025-05-01T00:00:00Z",
  "end_date": "2025-07-31T00:00:00Z",
  "recurrence": {
    "type": "monthly_days",
    "month_days": [1, 15]
  }
}
```

**На конкретные даты:**
```json
{
  "title": "Инвентаризация",
  "status": "new",
  "recurrence": {
    "type": "specific_dates",
    "specific_dates": [
      "2025-05-10T00:00:00Z",
      "2025-06-20T00:00:00Z"
    ]
  }
}
```

**По чётным числам:**
```json
{
  "title": "Еженедельный обход",
  "status": "new",
  "start_date": "2025-05-01T00:00:00Z",
  "end_date": "2025-05-31T00:00:00Z",
  "recurrence": {
    "type": "parity",
    "parity": "even"
  }
}
```

### Ответ

Возвращается массив созданных задач — по одной на каждую дату:

```json
[
  {
    "id": 10,
    "title": "Обзвон пациентов",
    "status": "new",
    "recurrence_id": 1,
    "scheduled_date": "2025-05-01T00:00:00Z",
    "created_at": "2025-04-06T10:00:00Z",
    "updated_at": "2025-04-06T10:00:00Z"
  }
]
```

## Допущения и решения

- **Диапазон дат обязателен** для типов `daily`, `monthly_days` и `parity`. Без него невозможно определить количество задач. Для `specific_dates` диапазон не нужен — даты заданы явно.
- **`month_days` от 1 до 30.** День 31 не поддерживается. Числа, которых нет в конкретном месяце (например, 30 февраля), пропускаются.
- **Каждая задача независима после создания.** Редактирование или удаление одной задачи не влияет на остальные.
- **Правило повторения неизменяемо.** После создания изменить `recurrence` нельзя — только удалить задачи и создать заново.
- **Генерация задач происходит сразу** при создании, а не по расписанию. Это упрощает архитектуру и не требует фонового воркера.
- **Статус по умолчанию** — `new`, если не указан явно.
